Overview

The application is a two-process, single-page dashboard for a fictional electronics factory. A Vite dev server serves the Vue front end on port 3000. A FastAPI process on port 8001 loads seven JSON files into memory at import time and answers read-only queries against them. There is no database, no authentication, and no persistence. Every request is a pure function over lists that were loaded once at startup.

System architecture

The browser talks directly to the API on a different origin. There is no Vite proxy; the client hardcodes http://localhost:8001/api and the backend allows all origins through CORS middleware.

Data flow

Global filter state lives in one composable as module-level refs. Because the refs are created once at module scope, every view that imports the composable shares the same objects. No Pinia, Vuex, or provide/inject is involved. A change in the filter bar therefore triggers watchers in whichever view is mounted, which re-queries the API.

API surface

Every route is a GET. The filter parameters are all optional strings. Warehouse matching is exact and case-sensitive, while category and status are compared lowercase. The month parameter accepts either YYYY-MM or a quarter key such as Q3-2025.

Known gaps

These were observed during the code read. They matter for anyone extending the app and are listed so the diagrams above are not mistaken for a complete picture.

AreaObservation
clientSix functions in api.js call task and purchase-order endpoints that do not exist on the server. The task fetch in App.vue fails silently on every page load.
clientviews/Backlog.vue has no route and is unreachable.
clientReports.vue uses the Options API, imports axios directly, hardcodes URLs, and ignores global filters. It is the outlier against every other view.
clientThe filter bar exposes months only. The backend also accepts quarter keys but the UI never sends them.
servertotal_backlog_items in the dashboard summary ignores all filters and is always the global count.
serverCORS combines a wildcard origin with credentials, which browsers reject for credentialed requests.
dataBacklog SKUs and transaction warehouse codes do not match the taxonomy used by inventory and orders. generate_data.py would regenerate the old taxonomy.
testsNo tests cover the orders or reports endpoints. The test docs claim 51 and 55 tests. The real count is 40. There are no frontend tests and no CI.
Static page, no external dependencies. Source of truth remains the code under client/ and server/.
